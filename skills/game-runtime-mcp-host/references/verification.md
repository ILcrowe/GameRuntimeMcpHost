# 런타임 검증

요청 결과를 증명하는 데 필요한 최소 증거만 사용한다.

## 상태 변경

1. 행동 전 관련 상태를 읽는다.
2. 행동 하나를 수행한다.
3. 가능하면 명시적인 행동 결과를 읽는다.
4. 행동 뒤 같은 관련 상태를 다시 읽는다.
5. 기대값과 실제값을 비교한다.

## 시각적 변경

1. 논리·런타임 상태를 먼저 검증한다.
2. 화면 결과가 중요하면 스크린샷 한 장을 캡처한다.
3. 스크린샷은 표현 결과만 확인하는 데 사용한다.

## 성능 변경

1. 관련 런타임·빌드 식별값을 기록한다.
2. 정의된 조건에서 기준 메트릭 스냅샷을 얻는다.
3. 필요한 변경은 이 전송 경로 밖에서 적용한다.
4. 새 빌드에 다시 연결한다.
5. 빌드 식별값이 예상대로 바뀌었는지 확인한다.
6. 같은 조건에서 비교 메트릭을 얻는다.
7. 같은 지표와 작업 부하를 비교한다.

## 실패 근거 우선순위

1. 권위 상태·결과 도구
2. 런타임 오류·결과 Payload
3. 필터된 증분 로그
4. 성능 문제일 때 메트릭
5. 표현 문제일 때 스크린샷

기본 동작으로 모든 진단 표면을 수집하지 않는다.
