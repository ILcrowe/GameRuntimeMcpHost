# 게임 플레이 제어

GameRuntimeMcpHost는 전송 계층이다. 합법 행동, 검증, 권위 상태 변경은 게임 소유 어댑터가 최종 결정한다.

## 낮은 추론량 행동 순서

게임 플레이 행동 요청에는 다음 순서를 따른다.

1. 정확히 일치하는 노출 도구를 찾는다.
2. 해당 도구에 필요한 최소 문맥을 읽는다.
3. 행동 하나를 제출한다.
4. 명시적인 행동 결과가 있으면 읽는다.
5. 영향받은 권위 상태를 다시 읽는다.
6. 요청한 상태가 검증되면 중단한다.

이 순서로 충분하면 관련 없는 도구를 탐색하지 않는다.

## 권한

- 모델은 행동을 제안한다.
- 게임 어댑터는 행동이 합법인지 결정한다.
- 게임 어댑터가 권위 상태를 변경한다.
- 거절된 행동을 더 낮은 수준의 범용 진단 호출로 우회하지 않는다.

## 재시도 규칙

### 읽기 전용 도구

이전 호출이 유효한 응답을 반환하지 않은 것이 명확하면 재연결 뒤 다시 호출할 수 있다.

### 멱등 상태 변경

도구 계약이 멱등성을 명시하거나 Idempotency·Action Key를 받는 경우에만 재시도한다.

### 비멱등 상태 변경

타임아웃 또는 연결 손실 뒤에는 다음 순서를 따른다.

1. 즉시 다시 제출하지 않는다.
2. 가능한 경우 원래 Action ID로 행동 결과·상태를 조회한다.
3. 권위 상태를 다시 읽는다.
4. 행동이 실행되지 않았다는 근거가 있고 도구 계약이 재시도를 허용할 때만 다시 제출한다.

## 턴·의사결정 절차

노출된 경우 다음 고정 순서를 우선한다.

`대기 중 의사결정 -> 문맥 -> 행동 제출 -> 행동 결과 -> 갱신 상태`

런타임 재연결 또는 Turn Revision 변경 뒤 오래된 문맥으로 행동을 제출하지 않는다.

## Unity 게임 플레이 샘플
